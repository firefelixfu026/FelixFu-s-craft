## 1. 项目概览

这是付江樊的个人博客和管理工具平台。最初目标是个人主页、文章系统和后台管理，后续扩展了评论、账号、AI 写作辅助、运维面板、备份中心、学习助手、微信群 bot 语料工作台、暑期冲刺计划等模块。

项目目前是一个完整的前后端分离应用：

- 前端：React + Vite，负责首页、文章、计划、账号、管理后台和交互体验。
- 后端：FastAPI + SQLAlchemy + Pydantic，负责 API、认证、文章、评论、图片、AI 配置、运维状态等。
- 数据库：PostgreSQL。
- 部署：Docker Compose 启动前端、后端、数据库，宿主机 Nginx 做 HTTPS 和反向代理。
- 自动化：GitHub Actions 先跑 CI，成功后自动 SSH 到服务器部署。

## 4. 本地启动

第一次启动：

```powershell
Copy-Item .env.example .env
docker compose up -d --build
```

访问：

- 前端：`http://127.0.0.1:8080`
- 后端健康检查：`http://127.0.0.1:8000/api/health`
- 经前端代理访问健康检查：`http://127.0.0.1:8080/api/health`

常用检查：

```powershell

```

前端单独构建：

```powershell

npm ci
npm run build
```

后端导入检查：

```powershell

python -c "from app.main import app; print(app.title, app.version)"
```

## 5. 线上部署流程

GitHub Actions 有两个主要流程：

- `.github/workflows/ci.yml`
  - 后端：Python 3.12 编译检查和 FastAPI app 导入检查。
  - 前端：Node 22，执行 `npm ci` 和 `npm run build`。
  - Compose：执行 `docker compose config`。
- `.github/workflows/deploy.yml`
  - CI 成功后触发，或手动触发。
  - 使用 GitHub Secrets 中的服务器信息 SSH 到服务器。
  - 进入 `DEPLOY_PATH`，默认 `/opt/felixfu-blog`。
  - 执行 `git pull --ff-only` 和 `scripts/deploy-production.sh`。

生产部署脚本会执行：

```bash
docker compose up -d --build
docker compose ps
curl -f http://127.0.0.1:8000/api/health
curl -f -I http://127.0.0.1:8080
```

如果自动部署失败，优先看：

- GitHub Actions 的 CI 是否通过。
- GitHub Actions 的 Deploy 日志。
- 服务器 `/opt/felixfu-blog` 是否能正常 `git pull`。
- 服务器 Docker 容器是否健康。
- 宿主机 Nginx 是否仍然能代理到 `127.0.0.1:8080` 和 `127.0.0.1:8000`。

## 6. 环境变量

不要把真实 `.env`、密钥、Token、数据库密码提交到仓库。

重要配置项：

- `DATABASE_URL`：后端连接 PostgreSQL。
- `AUTH_SECRET`：登录 token 签名密钥，线上必须使用强随机值。
- `AUTH_TOKEN_TTL_SECONDS`：登录保持时间，目前用于刷新后不需要重新登录。
- `ADMIN_SETUP_TOKEN`：初始化管理员用。
- `ADMIN_COMMENTS_REQUIRE_APPROVAL`：管理员评论是否也需要审核。
- `ALLOW_PUBLIC_EMAIL_REGISTRATION`：是否允许普通用户自行注册邮箱账号。
- `ALLOW_READER_EMAIL_LOGIN`：是否允许普通读者使用邮箱登录。
- `LOGIN_FAILURE_LIMIT` / `LOGIN_LOCK_SECONDS`：登录失败限流。
- `GITHUB_CLIENT_ID` / `GITHUB_CLIENT_SECRET`：GitHub OAuth。
- `GITHUB_OAUTH_CALLBACK_URL`：GitHub 回调地址，线上应匹配 GitHub OAuth App 设置。
- `GITHUB_ADMIN_LOGINS` / `GITHUB_ADMIN_EMAILS`：GitHub 管理员白名单。
- `AI_PROVIDER_NAME`、`AI_API_STYLE`、`AI_BASE_URL`、`AI_MODEL`、`AI_API_KEY`、`AI_REQUEST_TIMEOUT`：AI 接入配置。

AI 配置已经支持管理员在前端保存、停用、删除。后台会持久化配置，不用每次手动改服务器环境变量；不过真实 API Key 仍然应当只在可信后台里填写。

## 7. 数据与备份

核心数据位置：

- PostgreSQL 数据：Docker volume `felixfu-blog_postgres_data`
- 上传图片：Docker volume `felixfu-blog_uploads_data`
- 后端持久文件：Docker volume `felixfu-blog_backend_data`

备份方式建议分两层：

1. 阿里云快照
   - 适合大改、上线、迁移前兜底。
   - 已创建过系统盘快照，可用于整机回滚或创建镜像。
2. 项目脚本备份
   - `scripts/backup-postgres.sh`：备份 PostgreSQL，默认保留 14 天。
   - `scripts/restore-postgres.sh`：恢复 PostgreSQL，恢复前会先做安全备份。

服务器上执行数据库备份：

```bash
cd /opt/felixfu-blog
./scripts/backup-postgres.sh
```

恢复数据库：

```bash
cd /opt/felixfu-blog
./scripts/restore-postgres.sh backups/postgres/felix_blog_YYYYMMDD_HHMMSS.sql.gz
```

大改前建议顺序：

1. 创建阿里云快照。
2. 执行数据库脚本备份。
3. 确认 `docker compose ps` 三个容器健康。
4. 再进行部署或数据迁移。

- 文章列表、详情、搜索、标签、分类、月份归档。

### AI

- 支持 OpenAI 兼容接口或 Codex 风格中转接口。
- 未配置真实模型时使用本地占位内容，保证页面可用。
- 管理员可在前端填写参数、保存、测试、停用、删除。
- AI 写作辅助支持润色、续写、大纲、写作模板和草稿历史。

## 9. 常见问题

### GitHub 登录出现 502

通常不是前端按钮问题，而是 Nginx 代理到后端时后端异常或后端不可达。排查顺序：

1. 访问 `https://www.felixfu.xyz/api/health`。
2. 在服务器执行 `docker compose ps`。
3. 查看后端日志：`docker compose logs backend --tail=120`。
4. 检查 GitHub OAuth App 的 callback URL 是否与 `GITHUB_OAUTH_CALLBACK_URL` 一致。
5. 检查 `GITHUB_CLIENT_ID` 和 `GITHUB_CLIENT_SECRET` 是否在服务器 `.env` 中存在。

### 首页或后台显示“页面刚刚卡住了”

前端全局错误保护会把错误展示出来，方便定位。处理方法：

1. 记录页面上显示的错误文本。
2. 回到首页确认其他页面是否可用。
3. 到后台安全页读取前端错误日志。
4. 如果是刚部署后的问题，优先清浏览器缓存或等待新版本资源加载。

### 推送 GitHub 很慢或失败

本机网络环境下曾经需要代理。可使用：

```powershell
git -c http.proxy=http://127.0.0.1:7897 -c https.proxy=http://127.0.0.1:7897 push origin main
```

### PowerShell 里中文显示乱码

文档本身是 UTF-8，乱码多半是终端编码显示问题。不要因为终端乱码就直接重写整份文档。

## 11. 后续优化建议

优先级较高：

- 给首页、文章、管理后台补一组 Playwright 冒烟测试，覆盖桌面和移动端。
- 继续扫暗色模式中的低对比度文字，尤其是表单、空状态、禁用按钮、统计卡片。
- 给 GitHub OAuth 和 AI 配置页增加更明确的错误提示。
- 把备份记录做成真实后端数据，而不只是前端登记。
- 定期把阿里云快照和数据库脚本备份结合起来，形成固定备份节奏。

中期可以做：

- 评论邮件通知或站内通知。
- 文章全文搜索索引。
- 文章版本历史和回滚。
- 图片去重、压缩和未使用图片清理。
- 学习助手接入真实任务计划和复盘记录。
- 微信群 bot 语料导入、匿名化和风格标签。
- 站点访问统计和性能面板。

可以暂缓：

- 更复杂的多角色权限系统。
- 大规模 CMS 化。
- 多服务器部署。
- 过早引入复杂队列、对象存储和独立监控平台。

## 12. 接手原则

- 改 UI 前先同时看日间、夜间、移动端。
- 改认证前先确认游客仍能访问公开主页和文章。
- 改部署前先做快照和数据库备份。
- 改 AI 前不要把 API Key 写进 Git。
- 改数据库字段时优先兼容已有数据，避免破坏线上旧记录。
- 发现线上 502 时先看后端健康和容器日志，再看前端。
